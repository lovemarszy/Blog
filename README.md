# THIS IS MY BLOG

## 框架升级实验（2026-10-09）

实验分支：`codex/nextra-upgrade`。已在独立 Vercel 项目完成云端构建、页面和分享图片验证，站点主人实际浏览及分享后确认可安排正式切换。代码尚未提交、推送或合并。

目标是保留现有网址、文章写法、导航、外观、图片与视频、标签、RSS、分享预览和统计功能。

### 当前路线

| 项目               | 原版本  | 实验版本 |
| ------------------ | ------- | -------- |
| Nextra / 博客主题  | 2.13.4  | 3.3.1    |
| Next.js / 配套工具 | 14.2.35 | 15.5.27  |
| React              | 18.3.1  | 保持不变 |
| Tailwind CSS       | 3.x     | 保持不变 |

这是过渡升级，并非升级到了最新架构。Nextra 4 只支持 App Router，需要另做页面迁移；不能仅修改版本号。保留现有主题的样式和行为是本次优先事项。

### 文件改动与用途

- `package.json`、`pnpm-lock.yaml`：升级现有框架及配套版本，重新解析它们的间接依赖。没有新增直接依赖；锁文件大部分变动来自新版 Nextra 的编译工具链。
- `pages/_app.mdx` → `pages/_app.tsx`：Nextra 3 不再支持 MDX 应用入口。保留本地字体、RSS 入口和统计组件，并增加页面样式范围标记。
- `types/styles.d.ts`：让 TypeScript 能识别入口里的全局 CSS 导入。
- `components/posts.tsx`：在页面渲染时读取 Nextra 页面目录，避免新版初始化顺序导致构建失败。保留排序、标题、中文日期和链接；明确指定旧版深色文字颜色。
- `styles/main.css`：适配主题从 `nx-` 到 `_` 的样式名称变化，恢复旧版深色颜色；隐藏主题新生成的重复文章列表，保留标签页原有标题和间距表现。
- `theme.config.tsx`：保留外部链接新窗口打开时供屏幕阅读器读取的提示。页脚、日期格式和分享头信息保持原有配置。
- `pages/posts/BeEngaging.md`：将原有电脑本地图片引用改为相同地址的 HTML 图片。新版静态图片编译会把该地址当成项目文件并导致构建失败；旧版是浏览器请求这个地址。未替换图片、未改文章内容。
- `renovate.json`：允许后续 Nextra 3 和 Next.js 15 补丁更新，继续阻止未经迁移的 Nextra 4 和 Next.js 16 自动升级。
- `pnpm-workspace.yaml`：将 Nextra 3 的 MathJax 链条中 `@xmldom/xmldom` 限制在修复漏洞的 0.9.12 及以上、0.10 以下版本。

### 验证与边界

项目没有独立的端到端测试套件。本次运行了 `pnpm check` 和 `pnpm build`，并以升级前生产构建作为对比基线。

- 类型检查、代码检查、15 篇文章元数据检查、生产构建、RSS 和站点地图生成通过。
- 27 个生成页面（包括错误页面）的路由清单一致。页面标题、SEO / 分享元数据、媒体地址和尺寸属性一致；忽略 Next.js 内部管理标记的变化。
- 浏览器在 1280px 桌面和 390px 手机宽度检查关键页面。桌面首页、文章目录、代表文章、标签详情、友情链接的主要元素尺寸、间距、字体、颜色和链接与基线一致。
- 摄影页最初因视频元数据加载时机出现高度差；用相同加载条件比较静态页面后布局一致。
- 用无脚本的生产 HTML 对比夹具检查文章目录、代表文章和摄影页的桌面与手机深色样式；这是样式验证，不等同于模拟系统主题切换。
- RSS、旧网址跳转、安全响应头、统计组件及分享签名逻辑保持原有实现。

仍需关注：

1. `OG_SIGNATURE_SECRET` 已由站点主人配置在 Vercel 环境变量中。本机缺少此变量，升级前后本机构建都报告相同警告；这不代表 Vercel 上缺少密钥。分享元数据可以比较，但签名图片服务需要在 Vercel 对应环境中完成端到端验证，Preview 是否也已配置尚未核实。只记录配置位置，不把密钥值写进仓库。
2. `BeEngaging.md` 的那张图片地址原本就不能在公开网站正常加载；本次只保留行为并解决升级构建阻碍。
3. 标签详情顶端原有 `[tag]` 标题和缺失的内文标签标题表现被保留，未趁升级改版。
4. `next lint` 在 Next.js 15 中已标记弃用，目前仍能通过；升级 Next.js 16 前需要迁移检查命令。
5. 运行依赖审计：旧版为 2 个严重、16 个高、18 个中、7 个低；升级并完成本轮安全补丁后，为 0 个严重、1 个高、2 个中、4 个低。相比基线没有新增告警，但仍有遗留问题，不能把此实验当成已完成安全验收的上线版本。GitHub 开放漏洞告警为空，与 npm 全量间接依赖审计并非同一范围。

### 后续迁移建议

先把这个过渡分支作为兼容性基线，由站点主人实际浏览确认。后续再迁移 Nextra 4 / App Router，将内容读取、标签、RSS 和分享元数据与主题展示分开，保留当前字号、间距、颜色和导航约定。以同样的 URL、元数据、媒体和浏览器对比逐项验收，再决定是否升级 React 19、Tailwind 4 和 Next.js 16。
